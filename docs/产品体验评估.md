# 会话回顾产品体验评估

评估日期：2026-10-02。基于真实 Web 操作、源码和边界测试；设计文档仅用于对照，不视为产品正确性的证明。下表保留最初评估，处理进展见文末。

| 优先级         | 场景与证据                                                                                                   | 用户影响                                                                               | 建议与取舍                                                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 高             | 真实 GPT-5.4 mini 请求降级后，回顾原样包含“不要调用工具”“只回复 Luna 状态确认”等用户指令                     | 虽有“事实整理”标签，仍像摘录而不是帮助接续工作的摘要；标签也不容易理解                 | 只用结构化任务状态提供简短降级，缺少可信材料时说明暂未生成；避免用原始用户指令充当当前任务。需决定失败时保留旧摘要、显示状态或不展示 |
| 高             | 自动回顾默认开启，当前可见会话闲置三分钟就调用模型；反而用户离开页面时停止自动生成                           | 阅读长回复可能触发额外请求；“回来接上工作”的价值与“前台闲置付费生成”的时机不完全一致   | 明确主要使用场景，比较手动优先、首次提示、返回时按需生成；不要直接增加更多开关                                                       |
| 高             | 任意设置改变都会使所有内存回顾失效，包括闲置阈值、并发数和命令开关（源码确认）                               | 设置了与摘要内容无关的选项，已经看见的摘要也消失，与“下条消息或刷新才清除”的直觉不一致 | 区分影响内容/路由的设置和只影响调度的设置；先确定保留旧摘要并标记过期的规则                                                          |
| 中             | 手动回顾使用命令行，自动回顾在没有合适命令行时使用轮次尾部；当前 SDK 没有通用聊天底部插槽                    | 同一功能出现的位置不同；旧命令行未必位于后续 Compact 下方                              | 争取宿主底部插槽，统一一个展示位置；不通过伪造会话事件或覆盖整个聊天界面解决                                                         |
| 中             | 默认最多 160 字符，UI 又支持三行折叠；551 字符测试显示长内容可展开，但更多内容是否存在主要靠省略号与图标表达 | 桌面下常没有展开必要，窄屏或长摘要的展开入口不够明显；字符硬截断也可能截掉下一步       | 简化为真正短摘要，或提供明确的“展开”文字；先确定摘要的信息优先级，避免只通过增加 token 解决                                          |
| 中             | `/recap settings` 只输出导航说明；空白新会话运行 `/recap` 后未观察到持久的无数据提示                         | 命令名称与行为预期不一致；空白场景可能让用户以为命令没生效                             | 若公开接口支持，直接打开设置；空会话明确提示需要先有对话。空白反馈还需核对宿主命令错误呈现                                           |
| 中             | 设置自动保存有 500ms 防抖，卸载会取消计时器/请求（源码）；保存失败或冲突需要留在页面处理                     | 修改后立即关闭设置可能丢失尚未提交的改动；“自动保存”容易被理解为关窗也保证保存         | 需要真实快速关闭专项验证；考虑失焦立即保存或关闭时提交，但保留 revision 冲突保护与明确失败反馈                                       |
| 中             | GPT-5.4 mini 在当前预算下本次真实测试降级；模型目录本身不保证每个模型都能在 512 tokens 内完整返回            | 为节省成本选择模型后可能反而反复失败；目前 UI 看不到失败原因和本次用量                 | 提供简明失败原因、重试建议或最近成功状态。不能据一次结果认定预算是根因，也不能承诺所有目录模型都兼容                                 |
| 中             | 刷新清除展示但不清除缓存；下一次闲置可重新显示缓存；`status` 也会恢复展示并解除本会话暂停（源码）            | “隐藏”“暂停”“查看状态”“重新生成”的区别不清楚                                           | 定义状态查询是否应有副作用，统一隐藏与暂停语义；减少难记的子命令                                                                     |
| 中             | 展示水位属于会话共享状态，关闭/刷新仍受多个标签页的可见性与心跳租约影响                                      | 不同窗口间可能互相影响，后台标签和超过租约的标签尤其需要清楚规则                       | 长期把展示生命周期与生成缓存分开。此次仅修复另一个仍可见标签页被误清除，不宣称解决全部多窗口产品语义                                 |
| 中             | 高级设置暴露缓存轮次、并发数、缓存会话数、上下文注入等；去掉生成方式后配置文件仍兼容 deterministic           | 大量技术选项让简单功能显得复杂，旧配置用户可能仍使用未在 UI 中显示的模式               | 默认页面只保留必要选项，技术项折叠；决定旧模式是迁移还是继续支持，不静默改变老用户成本语义                                           |
| 高（边界说明） | 文件路径开关只控制独立文件列表，消息中的路径仍可能进入模型；脱敏是模式匹配而非完整隐私过滤                   | 用户可能误以为关闭开关就绝不发送路径，或者所有秘密都会被过滤                           | 保持清晰说明，考虑更准确的名称。不要把启发式脱敏宣传为隐私保证；可选上下文注入仍应明确它改变持久消息                                 |

此次直接修复的三项是可复现的程序缺陷，见同日测试报告；以上产品取舍保持原行为，待确认后再实施。

## 本轮处理进展

- 已修复：失败不再摘录原话；保留旧摘要并显示失败原因、重试按钮。
- 已修复：调度设置不清除回顾；内容设置保留较早摘要、使缓存失效。
- 已修复：模型长度以目标约束，保留完整句子，超长安全拒绝；明确展开文字。
- 已修复：settings 命令直接打开弹窗，共用设置表单；空白会话通过官方 input.dock 补充命令反馈，真实页面已验证提示和设置弹窗。
- 已修复：保存队列跨面板关闭继续运行，失败与冲突草稿重开保留，重新读取后明确重试；不承诺浏览器进程被杀后仍能完成网络请求。
- 已修复：status 无恢复/解除暂停副作用；刷新后的页面不因同一缓存自动复用重现摘要。
- 已修复：页面身份与展示水位分离，后台页面超过租约后也不被其他页面刷新清除。
- 已修复：高级设置默认折叠；旧 deterministic 明确提示并可主动迁移，不静默开始收费调用。
- 已移除：文件路径开关及独立文件列表收集。兼容忽略旧布尔配置；说明消息仍可能包含路径和敏感信息。
- 用户明确暂缓：默认前台闲置三分钟的自动触发时机，保持现状。
- 宿主限制：当前 SDK 仅有 turnTail（操作行之前）和命令行位置，没有整个聊天底部/Compact 后插槽。未替换宿主 Compact、未伪造会话事件，也未将摘要搬到用户未要求的输入框区域。统一绝对底部仍待宿主公开扩展点。

重启后核心真实 Harness 验收已完成，发现的空白页命令反馈缺口已修复并现场复验；详细范围见《验证说明》最后一节。
