# DSH Recap · 会话回顾

**离开一会儿，回来就能接上之前的工作。**

[English](README.md) · [配置说明](docs/配置说明.md) · [源码仓库](https://github.com/lolipop-1x1/dsh-recap)

这是面向 **DeepSeek Harness 0.2.0-rc.2** 的非官方插件。它把当前会话的任务、可观察到的进展和有依据的下一步整理为聊天区域内的 `›recap ·` 文字。默认最多 160 字符，预览最多三行，点击展开可查看全文。不是跨会话记忆，也不会默认改写主模型上下文。

## 安装

需要 Node.js 22.19+。在本项目目录执行：

```sh
npm ci --ignore-scripts
npm run build
npm pack
```

然后在 Harness 的**创造模式**中，让 `plugin_manager` 使用 `install_bundle` 安装本项目的**绝对路径**，例如：

> 安装当前工作区的 DSH Recap 插件。使用 plugin_manager 的 install_bundle，target 为此项目的绝对路径。

本地目录必须先构建出 `dist/`。包已声明 `dsh.bundle.patch` 和 Client 入口，不需要手改用户 profile、运行时配置或 Harness 源码。已有同名 Recap 插件时，先在插件管理中停用旧插件，避免 `/recap` 名称冲突。安装后刷新浏览器，并在「设置 → 会话回顾」中配置。

生成的 `dsh-recap-0.1.0.tgz` 可用于分发。**本项目尚未发布到 npm**；维护者发布前应确认包名所有权，必要时改为自己的 scope，并同步修改 patch 的插件名称和 Client ModuleLoader ID。

## 使用

| 命令              | 作用                                             |
| ----------------- | ------------------------------------------------ |
| `/recap`          | 回顾当前会话；资料没有变化时复用已有结果         |
| `/recap refresh`  | 强制重新生成，也可用于模型恢复后的重试           |
| `/recap hide`     | 隐藏当前回顾并暂停本会话自动回顾；手动请求可恢复 |
| `/recap status`   | 展示已有回顾，不发起生成                         |
| `/recap settings` | 显示设置入口说明                                 |
| `/recap help`     | 显示命令帮助                                     |

命令确认受理后立即返回，Harness 随即清空已提交的输入；模型在后台生成，完成后更新同一个回顾位置，不修改随后输入的新草稿。重复请求合并进行中的生成或复用未变化的结果；强制刷新替换当前回顾。受理成功不代表模型已经生成完成。

| 自动触发         | 默认         | 说明                                           |
| ---------------- | ------------ | ---------------------------------------------- |
| 当前可见会话闲置 | 开启，3 分钟 | 键盘、点击和滚动重置计时；页面心跳不算用户操作 |

新建、打开或切换会话不生成回顾，只重新计时。自动触发要求当前展示的主会话已加载、至少完成 3 个有内容的轮次、Agent 空闲。主 Agent 忙碌时不生成；本轮结束后重新开始闲置计时。最后一个可见标签页离开时，取消自动任务，已生成回顾保持显示。

手动结果展示在最新 `/recap` 命令位置；没有当前轮次之后的回顾命令时，自动结果展示在轮次尾部。默认最多三行，支持展开与收起；重复调用不会堆叠卡片。开始新一轮、刷新或关闭页面后隐藏临时回顾，失焦或心跳过期不会清除。原生命令历史记录受理或状态，不再另存一份摘要正文；自动结果不新增会话事件。模型用一两句短文说明任务、进展和下一步；事实降级只使用已记录内容，不复制上次长回复，也不收集会话统计和上下文占用。历史错误不代表当前仍然阻塞，计划不能当成完成。

## 隐私与用量

默认不添加模型工具，不新增第三方服务，不向主模型注入回顾，不读取工作区文件作为摘要素材。`hybrid` 模式使用明确配置的服务商/模型，或跟随当前会话的完整路由；这些辅助调用仍然消耗额度并共享服务商限流。`deterministic` 模式只提取事实，完全不调用模型。

摘要素材不包含思考过程、图片、工具参数和成功工具的大段输出。常见凭据模式会被脱敏，但**这不是完整 DLP**，对话中的业务代码、路径和私人信息仍可能进入你配置的模型。关闭「包含文件路径」仅去掉独立路径列表，不保证删除消息中提及的路径。

生成的回顾缓存只保存在内存中。不过 Harness 自己的会话日志、命令结果及原生投影检查点可能落盘；开启「注入主模型」还会写入一条可回放消息。不能将本插件理解成完全无磁盘痕迹的隐私工具。

## 可靠性设计

同会话请求合并，全局默认最多两个模型请求。新一轮活动、配置变化、语言变化、关闭或卸载会取消相关旧任务；迟到结果不能覆盖新状态。模型超时、不完整输出或错误会回退为**明确标记的事实整理**。

缓存有会话数和轮次边界。默认资料变化后重新生成；可选的轮次缓存窗口可复用旧资料，手动 `refresh` 可跳过缓存。执行 `/recap hide` 后，当前已加载会话不会自动出现回顾；缓存淘汰也不会忘掉暂停状态。恢复后的新会话实例则重新判断。

自动生成依赖 Host 持续运行和浏览器可见状态心跳。电脑睡眠、Host 停止或连接断开时不触发。旧版离开、恢复、压缩及每轮结束设置兼容读取并忽略；目前仅保留手动和可见会话闲置两个入口。

## 开发与验证

```sh
npm run typecheck
npm test
npm run test:coverage
npm run test:browser
npm run format:check
npm run build
```

测试覆盖事实整理、调度与生命周期、真实 Harness 服务接入、认证 HTTP、隔离设置持久化、客户端注册和包入口。浏览器组件测试检查三行预览、展开收起、加载失败时保持安静、继续对话收起、设置冲突、语言切换、窄屏布局及卸载清理。测试不读取生产 profile 的凭据，不调用付费模型。

浏览器测试优先使用 macOS 已安装的 Chrome，也可通过 `CHROME_PATH` 指定，或使用 Playwright Chromium（`npx playwright install chromium`）。它使用独立组件页面；新 profile 安装和更换 Harness 版本仍需单独验收。

源码仓库的 `docs/` 目录保留设计与验证说明。已在真实 Harness 0.2.0-rc.2 页面使用合成会话验证 GPT-6-Luna 生成、文字展示、重复命令、提交后立即清空输入及新草稿保留；此前也验证过切换会话保持安静、可见会话闲置、降级、设置冲突与可选注入；具体覆盖与边界见 `docs/验证说明.md`。

目录分工：`src/core` 为无宿主依赖的事实与调度，`src/host` 为真实服务适配，`src/client` 为界面与原生插槽接入。设计与当前接口差异记录在 `docs/`。
